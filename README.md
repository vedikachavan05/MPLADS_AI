# MPLADS_AI

## AI-Powered MPLADS Monitoring & Analytics Platform

MPLADS_AI is an AI-powered monitoring and analytics platform designed to support transparent, data-driven monitoring of MPLADS-funded projects.

The platform combines structured MPLADS data, statistical analysis, machine learning, anomaly detection, and interactive dashboards to help identify unusual patterns, monitor fund utilization, and support further investigation.
##NOW PRORTYPE IS LIVE AT : https://mplads-ai-jade.vercel.app/

> **Note:** A risk signal generated by the platform is an analytical indicator for monitoring and investigation. It does not establish fraud, misconduct, or wrongdoing.

## 🚀 Key Features

### 1. Overview Dashboard

The Overview Dashboard provides a centralized view of the MPLADS data.

It includes:

- Total MPs monitored
- Total allocated amount
- Total recommended amount
- Total expenditure
- Fund utilization indicators
- Recommended and completed works
- Completion rate
- Transaction information
- Pending/in-progress payment indicators
- Financial allocation vs expenditure visualization
- Dataset statistics
- Anomaly summary

The dashboard is designed to give users a quick understanding of the overall system status.

---

## 2. MP Intelligence

The MP Intelligence module provides MP-level monitoring and risk analysis.

### MP Risk Directory

Users can:

- Search MPs by name
- Search by constituency
- Search by state
- Filter MPs with risk signals
- View MPs without current signals
- Navigate through paginated results

### MP Risk Detection

The platform combines two analytical approaches:

#### Statistical Detection

Statistical rules identify unusual values using distribution-based thresholds.

Current signals include:

- Low fund utilization
- High pending payments
- High unpaid vendor balance

#### Machine Learning Detection

An Isolation Forest model is used to identify unusual combinations of financial and operational characteristics.

The model considers multiple numerical indicators such as:

- Allocated amount
- Recommended amount
- Expenditure
- Utilization
- Recommended works
- Completed works
- Completion rate
- Unpaid balance
- Transaction count
- Successful payments
- Pending payments

Identity fields such as MP name and constituency are excluded from the ML model.

### Combined Risk Signal

The system combines statistical and ML signals to identify MPs requiring further analytical attention.

The platform distinguishes between:

- Statistical signal
- ML anomaly signal
- Combined signal

This helps users understand whether a flag originated from a specific rule, a multivariate ML pattern, or both.

## 4. Anomaly Detection

MPLADS_AI includes an anomaly detection layer for identifying unusual patterns in the available data.

The system currently uses:

### Statistical Anomaly Detection

Distribution-based rules such as IQR thresholds are used to identify unusually high or low values.

### Machine Learning Anomaly Detection

Isolation Forest is used for multivariate anomaly detection.

The ML model is designed to identify unusual combinations of characteristics rather than relying only on individual threshold violations.

### Explainable Signals

The platform provides supporting metrics so that an anomaly is not presented as an unexplained ML result.

## 6. Work Intelligence — Prototype

Work Intelligence is included as part of the platform architecture.

The planned module is intended to support:

- Work progress monitoring
- Delayed project identification
- Cost deviation analysis
- Cost overrun detection
- Duplicate-work detection
- Work-level anomaly detection
- Project status monitoring
- Recommendation-to-completion analysis

The current prototype does not treat unmatched records between datasets as reliable evidence of project-level irregularity.

For example, only reliably matched Work IDs are used when a comparison requires linking recommendation and completion records.

---

## 7. Payment Intelligence — Prototype

Payment Intelligence is part of the planned monitoring architecture.

It is intended to analyze:

- Payment activity
- Vendor patterns
- Repeated payment amounts
- Transaction frequency
- Pending payments
- Payment concentration
- Unusual payment patterns
- Payment-related anomaly indicators

The prototype architecture keeps payment analysis separate from MP-level intelligence so that users can investigate financial activity at different levels.
